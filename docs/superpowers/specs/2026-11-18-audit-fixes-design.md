# แก้ finding จาก audit 2026-11-18 (v3.3.2) — design

วันที่: 2026-11-18 · ที่มา: `docs/superpowers/notes/2026-11-18-audit-findings.md` (อ่านคู่กัน finding แต่ละข้อมีหลักฐานและเลขบรรทัดอยู่ที่นั่น)

## เจตนา

นายท่านชาโดว์ต้องการให้แก้ทุก finding ของ audit ที่ไม่ชนกับงาน (ก) (อีเว้นต์/ช่วยเลือกแบบใหม่) ให้จบในรอบเดียว แล้วส่งต่อให้โมเดลอื่นลงมือจากแผน ผู้ลงมือคุยกับนายท่านระหว่างทางไม่ได้ จึงต้องอ่านเอกสารนี้ + findings + `CLAUDE.md` แล้วทำได้เลย

เหตุผล: ให้งาน (ก) เริ่มบนฐานที่เทสตรวจได้จริง (ไม่เขียวหลอก), ตารางไม่หายตอน retry, และเอกสารตรงกับโค้ด

## ไม่ใช่เป้าหมาย

- **ไม่ลบโค้ดอีเว้นต์/ช่วยเลือกที่ตาย** (`SIM`, `MJ`, `EVENTS`, `buildEvents`, `drawEvents`, `WEIGHTS`…`outScore`, `fxScore`, `aiScan`, `placeBadges`) งาน (ก) จะตัดสินว่าเก็บอะไร
- ไม่เริ่มงาน (ก) ไม่ออกแบบแท็บอีเว้นต์ใหม่
- ไม่เพิ่ม dependency, ไม่สร้าง `package.json`, ไม่ใช้ jsdom
- ไม่แก้ S2/S3/S4/S7 (เป็นข้อมูล หรือความเสี่ยงต่ำที่ไม่ต้องทำ)
- ไม่ลบ `tools/snapshot-diff.mjs` และโฟลเดอร์ `src/` (`CLAUDE.md` §8 ห้าม)

## สิ่งที่ห้ามเกิด (anti-goals)

- เทสเขียวทั้งที่ไม่ได้ตรวจอะไร (ปัญหาเดียวกับ F1 ซ้ำ)
- เขียน `0` หรือ `null` ทับค่าเดิมในเกม หรือทับตารางที่อ่านได้แล้ว
- แทรก DOM เข้าไปในเกม หรือทำให้ observer สแกนทุกเฟรม (`CLAUDE.md` §5)
- ลบ listener keydown/keypress/keyup ที่ host (`CLAUDE.md` §6)
- `import()` ไฟล์ `app-*.js` หรือ `boot-*.js` (จะรันเกมชุดที่สอง)
- branch protection ที่ทำให้ `tools/release.mjs` push เข้า `main` ไม่ได้

## ข้อจำกัด

- สคริปต์เป็นไฟล์เดียว `wox-editor.user.js` ไม่มีขั้น build
- เทสรันด้วย `node --test "tests/**/*.test.mjs"` โหลดสคริปต์แบบ CommonJS แล้วได้ `LOC` (ทางออกก่อนแตะ DOM ที่ `if (typeof document === 'undefined')`)
- ทุกการแก้สคริปต์: `node --check`, bump `@version` + `VERSION` เป็น `3.3.2` พร้อมกัน, ปล่อยด้วย `node tools/release.mjs "ข้อความ"` (ลอง `--dry-run` ก่อน)
- ทำงานใน worktree/branch ของงานนี้ แตกจาก `audit/2026-11-18` (มีเอกสาร audit)
- `release.mjs` commit + push `main` ตรงๆ และ stage เฉพาะ `wox-editor.user.js`, `tools/release.mjs`, `tests/`, `.gitignore`, `CLAUDE.md`, `AGENTS.md`; ถ้าไม่มีอะไรให้ commit จะ throw ก่อน push
- ลำดับปล่อย (การตัดสินของผู้ออกแบบ): ทำงานทั้งหมดบน branch **โดยยังไม่ bump version** → checkout `main` ใน checkout หลัก (ตอนนี้อยู่ที่ `audit/2026-11-18`) → merge branch แบบ `--no-ff` (ไม่ push) → bump `@version` + `VERSION` เป็น `3.3.2` บน `main` → `node tools/release.mjs --dry-run "…"` → `node tools/release.mjs "…"` ซึ่ง push merge commit พร้อมกัน (และเป็นการทดสอบว่า S1 ไม่บล็อก push ปกติ)
- ไฟล์ `ABOUTME:` 2 บรรทัดบนสุดของไฟล์ใหม่ทุกไฟล์ที่รองรับคอมเมนต์
- ตอบ/เขียนเอกสารเป็นภาษาไทย คอมเมนต์ในโค้ดเป็นภาษาไทยตามไฟล์เดิม
- ไม่แยก subagent (นายท่านสั่ง: เปลือง token) ผู้ลงมือทำทุก task เองด้วย `superpowers:executing-plans`

## การออกแบบต่อ finding

หลัก: ตรรกะที่ตัดสินใจ (เลือกค่า, เรียง, ตรวจ) ย้ายเข้า `LOC` เป็น pure function ที่ห้าม throw และ export เพิ่มใน `return { … }` ของ `LOC`; โค้ดฝั่ง DOM เรียกใช้เท่านั้น ชื่อฟังก์ชันด้านล่างเป็นข้อเสนอ ผู้ลงมือเปลี่ยนได้ถ้าเหตุผลดีกว่า

### F1/T2 — เทส bundle อ่าน build ปัจจุบัน

- `tests/locate.test.mjs` เลิก hardcode `mwkobenp` และชื่อไฟล์ chunk
- เลือกโฟลเดอร์: env `WOX_BUNDLE` (ชื่อ BUILD หรือ path) ถ้ามี; ไม่งั้นโฟลเดอร์ใน `bundle/` ที่แก้ไขล่าสุด (mtime) ที่มี `index.html`
- derive ชื่อไฟล์เองด้วย `LOC.chunkChain` ทีละขั้น (index → boot → app) แบบเดียวกับ `loadCore` แล้ว assert: `boot` ขึ้นต้น `/b/boot-`, `app` ขึ้นต้น `/b/app-`, `core` ไม่ว่าง และทุก path ใน `core` มีไฟล์อยู่จริงในโฟลเดอร์
- assert ว่าตารางทั้ง 4 อยู่ใน core chunk ใดตัวหนึ่ง ด้วย marker ข้อความ (`id:"mortal"`, `id:"novice"`, `#8c918e`, `woodSword`) — **ห้าม import chunk** ในเทส
- ไม่มี `bundle/` เลย: ยังใช้ `t.skip` ได้ แต่ข้อความต้องบอกคำสั่ง `node tools/fetch-bundle.mjs` และ **แผนต้องรัน fetch ก่อนแล้วยืนยันว่า 0 skip**
- ชื่อเทสไม่ใส่ชื่อ build

### F2 — ตารางที่อ่านได้แล้วห้ามถูกทับด้วยค่าว่าง

- `LOC.keepTables(prev, next)` (pure): คืน object ตารางที่แต่ละคีย์ (`realms`, `martialRanks`, `tiers`, `items`) ใช้ `next[k]` ถ้าไม่เป็น null ไม่งั้นใช้ `prev[k]`
- `renderCore` ใช้ผลนี้สำหรับทั้ง 4 ตาราง (รวม `TIERS`) แทน guard แยกจุด
- เทส: รอบสองที่ `tiers: null` ต้องคง `tiers` ของรอบแรก; รอบสองที่มีค่าใหม่ต้องใช้ค่าใหม่

### F3 — `renderCore` throw ต้องไม่ทำให้ retry ตาย

- ใน `startCore`: ครอบ `renderCore(c)` ด้วย try/catch; ใน catch `console.error('[WoX Editor]', e)` (ต้องเห็นใน console ตามคอมเมนต์เดิม ห้ามกลืน) แล้วล้าง `corePromise` เมื่อ `corePromise === p`
- ลำดับ: ตัดสินใจล้าง `corePromise` จาก `LOC.coreLoaded(c)` **ก่อน** เรียก `renderCore` หรือใน `finally` — ผู้ลงมือเลือก แต่ต้องได้พฤติกรรม: throw → ล้าง; ผลไม่ครบ → ล้าง; ผลครบและไม่ throw → คงไว้
- สาเหตุ throw ที่รู้: `a.slot.localeCompare` เมื่อ `slot` ไม่ใช่สตริง → แก้ด้วยตัวเรียงของ F5 ที่ใช้ `String(x.slot ?? '')`
- เทส: ตัวเรียงของ F5 ไม่ throw เมื่อไอเทมไม่มี `slot`; ส่วน try/catch ตรวจในเกม (ผูก DOM)

### R1 — แสดงตารางที่อ่านได้แม้ chunk บางตัวล้ม

- `loadCore` เก็บ `out.failed = [path ที่ import ไม่ได้]` เพิ่มจาก `imported`
- `imported` และ `LOC.coreLoaded` **คงความหมายเดิม** (ครบทุกตัว) เพราะ `checkUpdate` ใช้กันการเขียนฐาน manifest ด้วยผลไม่ครบ
- `runHealth`: ถ้า `core` ไม่ว่างแต่ไม่ครบ ให้แสดง `✔` ของตารางที่เจอ, `–` ของตารางที่ไม่เจอว่า "ยังไม่แน่ใจ: chunk <ชื่อ> โหลดไม่ได้" (ห้ามขึ้น `✖`), แทนบรรทัดเดียว "ยังไม่ได้อ่าน chunk หลัก"
- ตรรกะสร้างบรรทัดเป็น pure: `LOC.tableLines(c, TABLES)` คืน array ของสตริง แล้วเทสทั้งสามกรณี (ครบ, บางส่วน, ไม่มี core)

### R2 — ไม่ดาวน์โหลด index/boot/app ซ้ำเมื่อ chain ได้แล้ว

- เก็บผล `chunkChain` ที่สมบูรณ์ (มี `app` และ `core` ไม่ว่าง) ไว้ในตัวแปรระดับหน้า `chainCache`; รอบ retry ใช้ cache แล้วข้าม fetch สามไฟล์ เพราะชื่อ chunk ไม่เปลี่ยนตลอดอายุหน้า
- import chunk ซ้ำไม่เสียเครือข่าย (module cache ของเบราว์เซอร์)
- ตรวจในเกม (network tab) ไม่ต้องมีเทส Node เพราะเป็นการเก็บตัวแปร

### R3 — บอกผู้ใช้เมื่อรอ state หมดเวลา

- `loadCore` ตั้ง `out.reason = 'no-state'` เมื่อ `waitState` คืน false
- `runHealth` แสดง "– รอข้อมูลเกมเกิน 2 นาที เล่นในเกมสัก 1 เดือนแล้วกดตรวจอีกครั้ง" แทน "ยังไม่ได้อ่าน chunk หลัก" (รวมใน `LOC.tableLines`)
- ไม่เพิ่มการเริ่มใหม่อัตโนมัติเมื่อ state มาทีหลัง (YAGNI; ปุ่มตรวจอีกครั้งทำได้อยู่แล้วเพราะ `corePromise` ถูกล้าง)

### F5 — เรียงและกรองไอเทม tier สตริง

- `LOC.tierIdx` ให้ tier สตริงระดับ (`common`, `uncommon`, `rare`, `epic`, `legendary`) แปลงเป็นลำดับ 0-4 ตาม `RAR_ORDER`; ตัวเลขคงเดิม 0-5; ค่าอื่นยัง `null`
  - เหตุผล: ตัวกรอง `#hqr` ใช้ index ของ `TIER_LBL` (6 ระดับ) แต่ไอเทมสตริงมี 5 ระดับที่ชื่อต่างกัน — การ map ตรง index ทำให้กรองได้และเรียงสูงก่อนต่ำ ผู้ลงมือต้องตรวจว่าการ map นี้ไม่ทำให้ป้ายชื่อขัดกับตัวกรอง (ป้ายยังมาจาก `tierOf` ซึ่งแสดงชื่อ `RAR_LBL` ถูกอยู่แล้ว)
  - ถ้าตรวจแล้วพบว่า map ตรง index ทำให้ผู้ใช้สับสน (เช่นกรอง "ขั้นมนุษย์" แล้วได้ไอเทม `uncommon`) ให้บันทึกเหตุผลใน journal และเลือกทางที่ชัดกว่า เช่น เพิ่มตัวเลือกกรองของระดับสตริงแยก
- `LOC.itemOrder(a, b)` (pure, ห้าม throw): เรียงระดับสูงก่อน → `null` ท้าย → `slot` ด้วย `String(slot ?? '')`; ใช้ทั้งใน `renderCore` (แทนบรรทัด `:593`) และ `drawItems` — **ที่เดียว**
- `LOC.tierMatches(item, filter)` (pure): `'all'` → true; `null` tier → true (เห็นทุกตัวกรองตามเดิม); ไม่งั้นเทียบ index
- เทส: tier ตัวเลข, สตริงตัวเลข, สตริงระดับ, undefined, ไอเทมไม่มี slot

### F6 — นโยบายค่าเข้าช่องเดียว

- ทุกช่องตัวเลข (เงิน, กรรม, ชื่อเสียง, ค่าพลังเดี่ยวและทั้งหมด, จำนวนในกระเป๋า, จำนวนเพิ่มไอเทม) ใช้ `LOC.numOr`
- ช่องว่างหรือไม่ใช่ตัวเลข: **ไม่เขียน** และ toast บอก "ใส่ตัวเลขก่อน" (ข้อผิดพลาด) — ไม่เขียน `0` ทับ
  - ยกเว้นกระเป๋า: ใส่ `0` ชัดๆ ยังลบไอเทมได้ตามเดิม ว่างคือไม่ทำอะไร
  - "บันทึกทั้งหมด" (`hsa`) ข้ามค่าพลังที่ช่องว่าง เขียนเฉพาะที่มีค่า
  - ช่องสายยุทธ์/ขั้นพลังที่ใช้ `?? 0` อยู่ (`stage`, `force`, `layer`, `qi`): เปลี่ยนเป็นคงค่าเดิมเมื่อว่าง (`?? t.martial.stage` ฯลฯ)
- `setStat`: `(t.stats ??= {})[k] = v` กัน throw
- ตรรกะ "ค่าใหม่หรือคงค่าเดิม" ถ้าแยกเป็น pure ได้ (เช่น `LOC.numOrKeep(x, prev)`) ให้เทส; การผูก toast ตรวจในเกม

### F7 — ตรวจระบบครอบฟิลด์ที่แผงเขียน

- `STATE_KEYS` ย้ายเข้า `LOC` แบ่งเป็นสองกลุ่ม:
  - จำเป็น: `money, stats, ageMonths, karma, fame, bag, realm, layer, qi` → ขาด = `✖`
  - มีหรือไม่มีก็ได้: `martial` (ตัวละครที่ไม่ได้อยู่สายยุทธ์ไม่มี), `pending` (ไม่มีเมื่อไม่มีอีเว้นต์ค้าง) → แสดงสถานะเป็น `–`/`✔` บอกว่ามีหรือไม่มี ไม่ใช่ `✖`
- `LOC.stateLines(t, statKeys)` (pure) สร้างบรรทัด state แล้วเทส
- ไม่ตรวจ `#choice-options` ในรอบนี้ (เป็นของงาน (ก))

### F4 — ข้อความแท็บอีเว้นต์

- เมื่อยังไม่รองรับ (`!SIM && !EVENTS.length`): `drawEvents` แสดง "อีเว้นต์/ช่วยเลือก: ยังไม่รองรับเกมแบบ bundle" แทน "ไม่พบอีเว้นต์ที่ตรงกับคำค้น"; ปุ่ม "เรียกอีเว้นต์นี้" toast ข้อความเดียวกันแทน "เลือกอีเว้นต์จากรายการก่อน"
- ใช้ข้อความคงที่ตัวเดียว (ตัวแปร) ทุกจุด รวมถึงที่ `renderCore` และ `runHealth`
- ไม่ลบโค้ดอื่นของแท็บ

### R4 — `fresh()` ไม่ทับช่องที่ผู้ใช้กำลังแก้

- เงื่อนไข focus ครอบ `INPUT`, `SELECT`, `TEXTAREA`

### R5/R6 — ไม่ทำงานเปล่าเมื่อไม่มีป้าย/ไม่มี SIM

- `placeBadges` ผูก `scroll`/`resize` ผ่าน `requestAnimationFrame` (ทำครั้งเดียวต่อเฟรม) และ return ทันทีเมื่อ `aiBadges` ว่างและไม่มี `.aibadge` ค้าง
- `aiObs.observe(...)` เรียกเฉพาะเมื่อมี `SIM` (ตอนนี้ไม่มี = ไม่เฝ้า) — ใส่คอมเมนต์ว่างาน (ก) ต้องเริ่ม observer เมื่อมีแหล่งข้อมูลอีเว้นต์

### R7 — status ไม่เขียนซ้ำ

- `setInterval` 1 วินาที เขียน `textContent`/`classList` เฉพาะเมื่อค่าต่างจากรอบก่อน

### R8/S5 — `dropStalePanels` แคบลงและวนอย่างปลอดภัย

### S1 — ป้องกัน `main` ผ่าน `gh`

- ใช้ `gh api` ตั้ง branch protection ของ `Jeffinz/wox-editor` `main`: **ห้าม force-push, ห้ามลบ branch**; ไม่บังคับ review, ไม่บังคับ status check
- **กฎต้องบังคับเจ้าของ repo ด้วย** (นายท่านเลือก): repo เป็นของบัญชีส่วนตัวและเจ้าของเป็นคนเดียวที่ push ถ้าไม่บังคับ admin กฎจะไม่กันใครเลย จุดประสงค์คือกัน agent หรือนายท่านเอง `git push --force` เข้า `main` โดยไม่ตั้งใจ — ใช้ ruleset ที่ไม่มี bypass actor หรือ classic protection ที่เปิด `enforce_admins`
- ถ้าวันหนึ่งต้อง force-push `main` จริง ต้องปิดกฎก่อน — เขียนคำสั่งปิด/เปิดกลับไว้ใน handoff
- ก่อนตั้ง: อ่านค่าปัจจุบัน (`gh api repos/Jeffinz/wox-editor/branches/main/protection`, 404 = ยังไม่มี) และบันทึกผลไว้ในแผน/journal
- หลังตั้ง: ยืนยันว่า `node tools/release.mjs` ยัง push ได้ (ใช้ตอนปล่อย v3.3.2 เป็นการทดสอบจริง)
- ผู้ลงมือต้องหาเอกสาร GitHub REST ของ branch protection ให้แน่ก่อนเขียน payload (ห้ามเดา field) — ทางเลือกคือ ruleset (`repos/{owner}/{repo}/rulesets`) ซึ่งทำสองกฎนี้ได้เหมือนกัน เลือกอันที่เอกสารรองรับสำหรับ repo public ส่วนตัว
- ตัวเลือกบังคับ review: เขียนในเอกสารว่าเป็นทางเลือกในอนาคต ไม่ตั้ง
- **นี่เป็นการแก้ค่าภายนอก repo** ต้องรายงานใน handoff ว่าตั้งอะไรไปและย้อนกลับอย่างไร
