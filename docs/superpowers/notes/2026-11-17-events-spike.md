การตั้งค่าที่พบบ่อย (2,134,242 / 2,181,184 / 2,193,005 / 2,202,934):


- `options` เป็น **array ของ id เท่านั้น** เพราะ `wr` ปิดท้ายด้วย `.map(o=>o.id)` (3,221,219) ไม่มีข้อความ ไม่มี `chance` ไม่มี `ok/fail`

### ยืนยันจากโค้ด vs ยังไม่ยืนยัน

ยืนยันจากโค้ด bundle แล้ว: `pending.options` เป็น id, `pending.rarity` มีบางเส้น, DOM มีข้อความตัวเลือก, มี `small.odds[data-stat]` พร้อมคำบอกช่วง, มีคลาส `r-*` และป้าย rarity (เฉพาะ rarity ที่ไม่ใช่ `common`), มี `.fate-pick`

ยังไม่ยืนยัน (ต้องเปิดเกมจริงดู):

- `t.pending.rarity` มีจริงทุกอีเว้นต์ในเซสชันจริงไหม (โค้ดบอกว่าบางเส้นไม่ตั้ง)
- การ์ดพิเศษ (`campaignTurn`, `auctionHall`, `dsMissionBoard`, การ์ดสงคราม) มี `.odds` ครบทุกปุ่มไหม — โค้ดบอกว่ามีเฉพาะตัวเลือกที่มี `chance.stat` หรือ `band`
- ข้อความคำบอกช่วงบนจอตรงกับตารางใน `c-577` ไหม (ถ้าเกมเปลี่ยนคำ ต้องแก้สำเนา)
- `t.log` ของทุกอีเว้นต์มี `rarity` ติดมาทุกครั้งไหม — โค้ด UI เองอ่าน `e.log.filter(h=>["epic","legendary"].includes(h.rarity))` (5,032,414) จึงมีอย่างน้อยบางรายการ แต่ยืนยันครบไม่ได้จากการอ่าน
- ชื่อ id/คลาสพวกนี้จะอยู่รอด build หน้าไหม

## 3. ทางเลือกและความเสี่ยง

### (ก) ใช้เท่าที่ได้จาก chunk หลัก + state + DOM

ทำได้แค่นี้:

- แท็บอีเว้นต์เปลี่ยนจาก "รายการอีเว้นต์ทั้งเกม" เป็น (1) การ์ดปัจจุบัน อ่าน `#choice-title`, `#choice-text`, `#choice.r-*`, `pending.options` จับคู่กับปุ่ม `#choice-<id>` แล้วโชว์ข้อความตัวเลือก + stat ที่ทดสอบ + ช่วงโอกาส + cost/fight; (2) บันทึกชีวิตนี้ อ่าน `t.log` (ข้อความ + rarity)
- ช่วยเลือกทำได้แค่ "ใบข้อมูล" ไม่ให้คะแนน เพราะ `fx`/`act` ของผลลัพธ์ไม่มีใน state และไม่มีใน DOM ถ้าฝืนให้คะแนนด้วยคำในข้อความ = แต่งข้อมูลขึ้นมา
- ทางเลือกเสริม: ปุ่ม "ให้เกมเลือกเอง" ที่คลิก `.fate-pick` ให้ (ผู้ใช้กดเอง ไม่ auto)

ความเสี่ยง: คุณค่าหลักของช่วยเลือก (ให้คะแนน เลือกดีที่สุด) หายไป เหลือข้อมูลที่การ์ดเกมโชว์อยู่แล้ว; ช่วงโอกาสหยาบ (bucket 40–75% กว้าง); ต้องเขียนตัวอ่าน DOM ใหม่และเพิ่มการตรวจในแผงตรวจระบบ; DOM เปลี่ยนได้ทุก build; `pending.rarity` อาจว่าง

### (ข) ตัดแท็บอีเว้นต์และช่วยเลือกออก

ลบแท็บ ลบโค้ดช่วยเลือก ลบบรรทัดสถานะที่ขึ้นว่า "ยังไม่รองรับ"

ความเสี่ยง: เสียความช่วยเหลือด้านอีเว้นต์ทั้งหมด; ต้องบอกผู้ใช้ตรงๆ ว่าเกมแบบ bundle ให้ไม่ได้; ของที่เหลือ (แก้ค่าหลัก/กระเป๋า) ยังทำงาน; โค้ดตายที่ `SIM`/`MJ`/`EVENTS` ต้องลบออกด้วย ไม่งั้นค้างไว้อ่านยาก; คีย์ `woxed.ai.*` ใน localStorage กลายเป็นของตาย

### (ค1) ขุดข้อมูลอีเว้นต์ออกมาจาก `app-*.js` ตอนพัฒนา แล้วฝังสำเนาไว้ในสคริปต์

**ไม่เข้าเงื่อนไข** — เนื้ออีเว้นต์ไม่ได้เป็น JSON แต่เป็นพริตตี้ของ factory (`lr`, `un`, `Pt`) ที่เรียกฟังก์ชันและกระจายค่าคงที่ร่วม การดึงออกมาต้องประเมิน body ของโมดูล = รันโค้ดของเกมซ้ำนอกหน้าเว็บ ขัด Global Constraint ข้อ "ห้ามรันโค้ดของ app ซ้ำ" และ "อ่านได้เฉพาะค่าที่อยู่ในหน่วยความจำของหน้าเกมตอนรัน" นอกจากนั้นยังเป็นการคัดลอกเนื้อหาเกมหลายเมกะไบต์ขึ้น repo สาธารณะ

### (ค2) `import()` ตัว `app-*.js` เพื่ออ่าน namespace

**ไม่เข้าเงื่อนไข** — Global Constraint ห้าม import `app-*.js`/`boot-*.js` และต่อให้ทำก็ได้ namespace ว่าง (ไม่มี `export{`)

### (ค3) ใช้ `window.wox` โดยเปิดหน้าเกมด้วย `?promo`

อยู่ในเงื่อนไข (อ่านค่าที่อยู่ในหน่วยความจำหน้าเกม ไม่ได้รันโค้ดซ้ำ) แต่ **ไม่พอ**: `window.wox` ไม่มี sim, ไม่มีตารางอีเว้นต์, ไม่มีข้อความตัวเลือก ส่วน `life` ที่มันให้ก็คือ state ที่สคริปต์ดักได้อยู่แล้ว และสคริปต์เติม `?promo` เองหลังโหลดไม่ได้ (ต้องโหลดหน้าใหม่) → ไม่มีอะไรเกินของเดิม

### (ค4) ถอดรหัส `d/*.bin` หรือใช้ key จาก `c-RCZEDD4B.js`

**ไม่เข้าเงื่อนไข** — Global Constraint ห้ามตรงๆ และไม่จำเป็นด้วย: build `mwkobenp` ฝังเนื้ออีเว้นต์ไว้ใน `app-*.js` ไม่ได้อยู่ใน bin

### (ค5) ดึง `/b/app-*.js` เป็นข้อความตอนรันแล้วไล่ regex เอาตาราง

**ไม่เข้าเงื่อนไข** — ขัดข้อ "อ่านได้เฉพาะค่าที่อยู่ในหน่วยความจำของหน้าเกมตอนรัน" (นี่คือการอ่านไฟล์ดิบนอกหน่วยความจำ) และในทางปฏิบัติทำไม่ได้ เพราะค่าที่ต้องการเป็น expression ไม่ใช่ JSON ต้องมี parser + evaluator อยู่ดี

### (ค6) พึ่งปุ่ม "ให้ฟ้าเลือก" ของเกม (`.fate-pick`)

อยู่ในเงื่อนไข ใช้ DOM ล้วน ไม่แตะอันดับ/ตลาด เหมาะเป็นปุ่มให้ผู้ใช้กดเองในโหมด bundle แต่ไม่ใช่ "ช่วยเลือก" ที่ให้คะแนน และสุ่ม จึงไม่รับประกันผล

## 4. ข้อเสนอ

ผมเสนอ **(ก) แบบจำกัดขอบเขต**: เก็บแท็บอีเว้นต์ไว้ในรูป "การ์ดปัจจุบัน + บันทึกชีวิตนี้" และลดช่วยเลือกเป็นใบข้อมูล (ข้อความตัวเลือก, stat ที่ทดสอบ, ช่วงโอกาส, ค่าใช้จ่าย, ความหายาก) พร้อมปุ่ม "ให้เกมเลือกเอง" ที่ผู้ใช้กดเอง ไม่มี auto-click และ **ไม่ให้คะแนน** เพราะคะแนนที่คำนวณจากคำในข้อความคือข้อมูลที่เราตั้งขึ้นเอง ซึ่งขัดกติกา "ไม่แต่งรายละเอียดทางเทคนิค" ตรงๆ ถ้าเจ้าของโปรเจกต์ต้องการให้ช่วยเลือกให้คะแนนได้เหมือนเดิม ทางเดียวที่ซื่อสัตย์คือเลือก **(ข) ตัดออก** แล้วบอกผู้ใช้ว่าเกมแบบ bundle ไม่ให้ข้อมูลนั้น — ดีกว่าเก็บแท็บที่ดูทำงานแต่ให้ข้อมูลปลอม

สิ่งที่ต้องยืนยันในเกมจริงก่อนลงมือ:

1. เปิดอีเว้นต์ major แล้วดูว่า `t.pending.rarity` มีค่า และ `#choice` มีคลาส `r-*` กับป้าย `.rarity-badge` จริง
2. ไล่ทุกปุ่มใน `#choice-options`: ปุ่มไหนมี `small.odds[data-stat]`, คำบอกช่วงที่เห็นตรงกับตารางใน `c-577`, ปุ่มที่ไม่มีการทดสอบมีอะไรบ้าง
3. ดู `t.log` หลังจบอีเว้นต์ 1-2 ครั้งว่า entry มี `rarity` และข้อความครบ
4. เปิดด้วย `?promo` ดูว่า `window.wox` โผล่จริง (เพื่อปิดทางเลือก ค3 ให้จบ)
5. หลังเกม build หน้า เช็กว่า id/คลาสชุดนี้ยังอยู่ แล้วให้แผงตรวจระบบเตือนเมื่อ `#choice-options` หาย

กฎตัดสิน: ถ้าข้อ 1 หรือข้อ 2 ไม่ผ่าน (ไม่มี `pending.rarity`/คลาส `r-*` หรือปุ่มส่วนใหญ่ไม่มี `.odds`) แปลว่า (ก) ให้ข้อมูลไม่พอจะคุ้มทำ → ใช้ (ข) ตัดแท็บและช่วยเลือกออก
