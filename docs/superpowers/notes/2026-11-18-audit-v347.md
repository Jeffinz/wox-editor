สิ่งที่ยังไม่มีหลักฐานคือการรันในเบราว์เซอร์จริงบน build `mwlvws3l` — เทสครอบเฉพาะระดับ LOC กับ marker ในไฟล์ chunk

รอบนี้เจอของใหม่ 5 ข้อ ระดับต่ำทั้งหมด ไม่มีข้อไหนทำให้ผู้ใช้เจออาการพังทันที และของเดิมที่ยังเปิด (C10-C14, S1, T4, T6) ไม่มีอะไรเปลี่ยน

## 1. ของใหม่

### A1 — ป้ายแนะนำและกดอัตโนมัติตายเงียบเมื่อเกมวาดการ์ดเดิมซ้ำ (ต่ำ-กลาง)

`:1149-1151` คีย์กันสแกนซ้ำคิดจาก `[t.pending.id, preset, mark, auto, ...btns.map(b => b.id)]` — ถ้าเกมสร้างปุ่มชุดใหม่ด้วย id เดิม คีย์ไม่เปลี่ยน `aiScan` จึงออกทันที และ `aiBadges` ยังชี้ปุ่มเก่าที่หลุดจาก DOM

`:1126` `if (!k.b.isConnected) continue;` ทำให้ `placeBadges` ลบป้ายเดิมทิ้งแล้วไม่วางใหม่ — ป้ายหายจนกว่าคีย์จะเปลี่ยน

ผลอีกทาง: ถ้าเกมวาดซ้ำในช่วงหน่วงก่อนกด `:1198` `if (t.pending !== pend || !best.b.isConnected) return;` จะไม่กด แล้วไม่มีรอบสแกนใหม่มาทดแทน (คีย์เดิม) การกดอัตโนมัติจึงเงียบไปทั้งการ์ด

มีเส้นทางจริงใน build `mwlvws3l`: ฟังก์ชัน `WV(e)` ล้าง `#choice-options` แล้วสร้างปุ่มใหม่ทุกครั้ง และถูกเรียกซ้ำด้วย `pending` ตัวเดิมในเส้นทาง `watchdog: a decision put again` และหลังขายของ (`...after:()=>{j8e(I),Qt(),WV(I.pending)}`)

ข้อเสนอ (เล็กที่สุด): เทียบตัวปุ่มจริงแทน/เพิ่มจาก id เช่นเก็บ `aiBtns = btns` แล้วสแกนใหม่เมื่อ `btns.length !== aiBtns.length || btns.some((b,i)=>b!==aiBtns[i])` หรือปล่อยให้ `aiKeyPrev=''` เมื่อเจอป้ายที่หลุดจาก DOM

### A2 — `aiScan` ไม่มี try/catch ของตัวเอง และผู้เรียกกลืน throw ทั้งคู่ (ต่ำ)

`:1158` `const ev = SIM.majorEvent(t.pending.id);` และ `:1162` `ev.options ?? []` อยู่นอก try (เฉพาะ `majorTexts` กับ `statOdds` ที่อยู่ใน try)

ผู้เรียกทั้งสองกลืน: `:923` `try { aiScan(); } catch (e) { console.error }` และ `:1209` `try { aiScan(); } catch { /* ignore */ }` — sim throw จึงจบที่ console ว่าง ๆ แท็บช่วยเลือกไม่มีข้อความอะไรเลย ขัดกับเจตนาของ R5 ใน v3.4.7 (ความล้มเหลวของ sim ต้องถึงผู้ใช้ทุกทาง)

ข้อเสนอ: ครอบเนื้อ `aiScan` (หรือเฉพาะ majorEvent/options) แล้วเขียนเหตุผลลง `#ai_out` แบบเดียวกับ `EV_UNSUPPORTED`

### A3 — ปุ่มบันทึกเขียนค่าที่ช่องเลือกแสดงอยู่ แม้ค่านั้นไม่ใช่ค่าของ state (ต่ำ)

`:1010` `if (!$('h_mrank').options.length) return toast(...)` กันเฉพาะกรณีตารางยังว่าง
`:1025` `if (!$('h_realm').options.length) …` เหมือนกัน

ถ้า `t.martial.rank` หรือ `t.realm` เป็น index ที่ไม่มีในรายการ (ตารางสั้นลง, ค่าเกินช่วง, ค่าติดลบ) การ `fill()` จะถูกเบราว์เซอร์เมิน ช่องโชว์ตัวเลือกแรก และกดบันทึกจะเขียน index 0 ทับค่าเดิมของเกม — `numOrKeep` ไม่ช่วยเพราะช่องนี้ไม่ว่าง

ยังไม่เกิดกับ build ปัจจุบัน (`rank`/`realm` เป็น index ในตารางของเกมเอง) แต่เป็นทางเขียนทับเงียบเหมือนกันกับที่ R6 แก้ไปแล้ว

ข้อเสนอ: เก็บค่า state ไว้ถ้ามันไม่ใช่หนึ่งใน option (หรือขึ้นข้อความ "ค่านี้ไม่อยู่ในตาราง รอโหลดตารางใหม่")

### A4 — `#hadd` ไม่ปลดคีย์ `b:<id>` ที่ค้างอยู่ (ต่ำ)

`:1049-1054` เพิ่มไอเทมแล้วไม่ `saved.add('b:' + id)` ต่างจาก `d.bset`/`d.bdel` (`:1047-1048`)

ผล: ถ้าผู้ใช้พิมพ์จำนวนของไอเทมนั้นค้างไว้ หลังเพิ่ม ไอเทมจะถูกสร้างแถวใหม่แล้วใส่ค่าที่พิมพ์ค้างกลับ (`:970`) ช่องจึงโชว์เลขเก่า ขณะที่ state เพิ่มไปแล้ว และ toast บอกว่าเพิ่มแล้ว

ข้อเสนอ: `saved.add('b:' + id)` ในเส้นทาง `hadd`

### A5 — ของประดับเล็ก ๆ (nit)

- `:929` `` :String(s) `` ไม่มีเว้นวรรค (อ่านไม่ผิด แต่เป็นการพิมพ์ตก)
- `:1111` `aiScan(true)` ส่งอาร์กิวเมนต์ที่ `aiScan` ไม่รับ (ไม่มีผล ไม่มีเทสอ้าง)
- `:1158` `const ev = SIM.majorEvent(...)` -> ถ้าคืน `undefined` จะออกที่ `:1160` โดยไม่ล้าง `aiTimer`/`aiPend` ของรอบก่อน (ตัวจับเวลาเดิมจะยิงแล้วเช็ก `t.pending !== pend` เอง จึงไม่กดผิด แต่เป็นทางที่ไม่มีใครปิด)
