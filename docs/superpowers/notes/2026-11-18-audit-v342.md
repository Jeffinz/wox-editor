## สรุป

finding จาก audit รอบก่อน (F1-F8) ปิดครบ: เทส bundle อ่าน build เอง, `keepTables` กันตารางถอย, `renderCore` มี try/catch, แท็บอีเว้นต์ทำงานจริง, tier สตริงกรองได้, ช่องว่างไม่เขียน 0, ตรวจระบบมี `martial`/`pending`, `AGENTS.md` เขียนใหม่เป็นตัวชี้

รอบนี้เจอ 14 ข้อของโค้ด (C1-C14) ควรแก้จริง 4 ข้อ (C1, C2, T1, C6) ที่เหลือเป็นเรื่องเอกสารและเทส ไม่มีช่องโหว่ security ระดับรันโค้ดจากภายนอก

## 1. ข้อที่ควรแก้

### C1 — แผงไม่รีเฟรชค่าหลังจับ state ได้ครั้งแรก (กลาง)

`fresh()` ถูกเรียกแค่ 3 ที่: `wox-editor.user.js:799` (หลังอ่าน chunk), `:930` (หลังกดบันทึก), `:1140` (`wait` ซึ่ง `clearInterval` ทิ้งเมื่อสำเร็จครั้งแรก)

ผล: หลังเชื่อมต่อได้ เงิน/ค่าพลัง/กระเป๋า/สายยุทธ์ในแผงค้างที่ค่าเดิมตลอดจนผู้ใช้กดบันทึกเอง ตัวเลขบนหัวแผง (`#hs`) เปลี่ยนแค่ "เชื่อมต่อแล้ว/รอข้อมูล" เพราะ `setInterval` ที่ `:856` เขียนเฉพาะตอนสถานะเปลี่ยน

ข้อเสนอ: รีเฟรชเป็นรอบ (เช่น 2 วินาที) โดยใช้ guard เดิมที่ `:835` ที่ข้ามช่องที่ focus อยู่ หรือรีเฟรชตอนเปิดแท็บ/ตอนกาง `<details>`

### C2 — `aiScan` สแกนซ้ำทุก mutation เมื่อ sim ไม่รู้จักอีเว้นต์ที่ค้าง (กลาง)

`:1032-1033` `const ev = SIM.majorEvent(t.pending.id); if (!ev) { aiOut.textContent = ''; return; }` — return ก่อน `aiSig = sig` ที่ `:1034`
`:1031` เส้นทาง `!SIM?.majorEvent` ก็ return ก่อนตั้ง `aiSig` เช่นกัน

ผล: การ์ดอีเว้นต์ที่ไม่อยู่ใน Map ของ sim (เช่นอีเว้นต์ที่สร้างตอนรัน) ทำให้ `aiScan` ทำงานใหม่ทุกครั้งที่ observer ยิง แทนที่จะจำ sig ไว้ — ตรงกับบทเรียนใน `CLAUDE.md` §5 ที่เคยทำให้ช่วยเลือกไม่ทำงาน แต่กลับด้าน (สแกนเกิน ไม่ใช่ขาด)

ข้อเสนอ: ตั้ง `aiSig = sig` ก่อนการเช็ก sim และเก็บผล "ไม่รู้จักอีเว้นต์" เป็นสถานะแยก แล้วล้างเมื่อ sig เปลี่ยน

### T1 — `tools/release.mjs` ปล่อยผ่านได้ทั้งที่เทส bundle skip หมด (กลาง-สูง)

`:32` เช็กแค่ว่า `node --test` exit 0 ไม่ได้ดู `# skipped`
`tests/locate.test.mjs:16-35` ข้ามเทสที่ใช้ไฟล์จริงเมื่อไม่มี `bundle/` และ `bundle/` ถูก gitignore

พิสูจน์: `WOX_BUNDLE=nope node --test "tests/**/*.test.mjs"` → `pass 53, skipped 5` และ exit 0
ผลคือ clone ใหม่หรือ worktree ที่ไม่มี `bundle/` ปล่อยเวอร์ชันได้โดยไม่มีการตรวจ build จริงเลย (HANDOFF เคยเจออาการนี้และแก้ด้วยวินัย ไม่ใช่ด้วยโค้ด)

ข้อเสนอ: ให้ release อ่าน output แล้ว fail เมื่อ `skipped > 0`

### C6 — ป้ายตัวกรองระดับไอเทมมาจากค่าคงที่ ไม่ใช่ตารางเกม (ต่ำ-กลาง)

`$('hqr').innerHTML` สร้างจาก `LOC.TIER_LBL` (`:654`, ค่าคงที่ `:72`) แต่ป้ายในกระเป๋าใช้ `TIERS` ของเกมผ่าน `LOC.tierOf`
ตอนนี้ข้อความตรงกัน แต่สีไม่ตรง: build `mwlnu1rf` (`bundle/mwlnu1rf/b/c-KKS5VPJ2.js`) แถว 2 คือ `{th:"ขั้นมนุษย์",en:"Human grade",color:"#b8693e"}` ขณะที่ `TIER_LBL[1]` เป็น `#c9c9c0`

ผล: ถ้าเกมเปลี่ยนชื่อขั้น ตัวกรองกับรายการจะเรียกชื่อต่างกัน และตัวกรองสร้างครั้งเดียวก่อน `TIERS` มาถึง

ข้อเสนอ: สร้างตัวเลือก `#hqr` ใหม่ใน `renderCore` เมื่อมี `TIERS` แล้วถอยไปใช้ `TIER_LBL` เมื่อไม่มี
