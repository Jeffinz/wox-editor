## 1. ของใหม่

### N1 — `dirty` ไม่มีทางถูกล้างนอกจากกดบันทึก แผงหยุดรีเฟรชทั้ง session (กลาง)

`:888` ตั้ง `dirty = true` ทุกครั้งที่มี `input` ในช่องที่ `LOC.isStateField` รับ
`:892` `fresh()` ออกทันทีเมื่อ `dirty` และ `dirty` ถูกล้างเฉพาะใน `fresh(true)` (`:853` หลังอ่าน chunk, `:992` หลังกดบันทึกสำเร็จ)
`:1190` ตัวเรียกเป็นรอบคือ `setInterval(() => fresh(), 2000)` ซึ่งไม่ส่ง `force`

ผล: พิมพ์อะไรค้างในช่องเงิน/ค่าพลัง/จำนวนไอเทม แล้วคลิกออกไปที่เกมโดยไม่กดบันทึก — `fresh()` ข้ามทุกรอบตลอดไป เงิน ค่าพลัง กระเป๋า สายยุทธ์ในแผงค้างที่ค่าเก่า ไม่มีข้อความบอกผู้ใช้ (จุดสถานะยังขึ้น "เชื่อมต่อแล้ว")

ผลข้างเคียงอีกทาง: ถ้าผู้ใช้แก้ช่องหนึ่งค้างไว้ แล้วไปกดบันทึกอีกช่อง `fresh(true)` จะเขียนทับค่าที่พิมพ์ค้างไว้

ข้อเสนอ: เปลี่ยน `dirty` เป็นชุด id ของช่องที่แก้ (`Set`) แล้วให้ `fresh()` เขียนเฉพาะช่องที่ไม่อยู่ในชุด — ค่าที่ค้างไม่หาย และช่องอื่นยังรีเฟรช ทางลัดที่ถูกกว่า: ล้าง `dirty` เมื่อ `focusout` และค่าที่พิมพ์เท่ากับค่าใน state อยู่แล้ว

### N2 — ตัวจับเวลากดอัตโนมัติค้างได้ ทำให้กดทั้งที่คะแนนเท่ากัน (ต่ำ)

`:1112-1120` ถ้า `cfg.auto` เปิดและ `best` เป็น null (คะแนนเท่ากันหมด หรือทุกตัว blind) ไม่มีสาขาไหนเรียก `clearTimeout(aiTimer)`
ถ้ารอบก่อนหน้ามีการตั้งเวลาไว้และคีย์ยังไม่เปลี่ยน (เช่นผู้ใช้เปลี่ยน `ai_delay` แล้ว `aiKeyPrev=''` บังคับสแกนใหม่, หรือเปลี่ยน preset ในจังหวะที่ผลออกมาเท่ากัน) ตัวจับเวลาเก่าจะยิง ตรวจแค่ `t.pending !== pend` กับปุ่มยังต่ออยู่ แล้วกดปุ่มเดิม ทั้งที่สถานะปัจจุบันคือ "เท่ากันหมด — ไม่กด"

ผล: ขัดกับกติกา v3.4.5 ข้อ "คะแนนเท่ากันทั้งหมดต้องไม่กดอัตโนมัติ" ในจังหวะแคบ ๆ
ข้อเสนอ: เพิ่ม `else { clearTimeout(aiTimer); aiPend = null; }` ต่อท้าย `:1113` หรือย้าย `clearTimeout(aiTimer); aiPend = null;` ขึ้นไปก่อนสาขาการกด

### N3 — `stateLines` พิมพ์ `undefined undefined` เมื่อ `pending` เป็น object ว่าง (ต่ำ)

`:200` `✔ pending: ${t.pending.kind} ${t.pending.id}` ไม่กันค่าว่าง
ในเกมปกติไม่เกิด (pending มี `kind`/`id` เสมอ) แต่ถ้าเกมเปลี่ยนรูปร่าง pending แผงตรวจระบบจะขึ้นข้อความที่อ่านไม่รู้เรื่องแทนที่จะบอกว่า "pending รูปร่างไม่ตรง"
ข้อเสนอ: ถ้าไม่มี `kind` หรือ `id` ให้ขึ้น `– pending: รูปร่างไม่ตรง`

### N4 — สีระดับไอเทม interpolate ลง `style` โดยไม่ผ่าน `esc` (ต่ำ)

`:906` `style="background:${rarDot(itemRar(ITEMS[id])[1])}"` — ค่ามาจากตาราง `TIERS` ของเกม ถ้าเกมเปลี่ยนค่าสีเป็นสตริงที่มี `"` จะหลุดออกจาก attribute ได้
ความเสี่ยงจริงต่ำมาก (ข้อมูลมาจาก origin เดียวกัน) แต่จุดอื่นในไฟล์ escape หมด ข้อนี้จึงเป็นข้อยกเว้นตัวเดียว
ข้อเสนอ: `esc(...)` ค่าสี หรือตรวจว่าเป็น `#rrggbb` ก่อนใช้
