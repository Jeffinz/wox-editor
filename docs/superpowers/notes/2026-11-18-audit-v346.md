## 1. ของใหม่

### R1 — กระเป๋าทั้งลิสต์หยุดรีเฟรชเมื่อมีช่องกระเป๋าค้าง และไม่มีอะไรบอกผู้ใช้ (กลาง)

`:943` `const bagLocked = [...dirty].some((k) => k.startsWith('b:'));`
`:944` ถ้า `bagLocked` เป็นจริง จะไม่สร้างแถวกระเป๋าใหม่เลยทั้งบล็อก

ผล: พิมพ์เลขในช่องจำนวนไอเทมแถวเดียว (หรือพิมพ์แล้วลบกลับ) โดยไม่กด "ตั้ง"/"ลบ" — ลิสต์กระเป๋าทั้งก้อนหยุดอัปเดตตลอด session ที่เหลือ ค่าของไอเทมอื่นที่เกมเพิ่ม/ลดระหว่างเล่นค้างที่ตัวเลขเก่า และไอเทมที่เพิ่งได้มาในเกมจะไม่ขึ้นในแผงจนกว่าจะกดบันทึกหรือช่องนั้นหายไป (มีเฉพาะ `dirtyEl` ที่ปลดคีย์ให้เมื่อแถวถูกเกมลบ)

ผลข้างเคียงอีกทาง: `#hadd` เพิ่มไอเทมใหม่แล้วเรียก `fresh()` — ถ้ามีช่องค้างอยู่ ไอเทมที่เพิ่งเพิ่มไม่โผล่ในลิสต์ แต่ toast บอกว่าเพิ่มแล้ว ผู้ใช้จะงง

นี่คือส่วนที่ N1 เหลือค้าง: v3.4.5 เสนอสองทาง (Set ต่อช่อง หรือล้าง `dirty` เมื่อ focusout แล้วค่าเท่ากับ state) รอบนั้นเลือกทางแรกและแก้แค่ระดับช่อง แต่ระดับรายการยังล็อกทั้งก้อน

ข้อเสนอ (เลือกทางเดียว):
1. สร้างแถวใหม่เฉพาะแถวที่ไม่อยู่ใน `dirty` โดยคงค่าในช่องที่ค้างไว้ (อ่านค่าที่พิมพ์ไว้ก่อนเขียน `innerHTML` แล้วใส่กลับ) — ถูกที่สุดที่ยังคงพฤติกรรม
2. หรือล้างคีย์ออกเมื่อ `focusout` และค่าที่พิมพ์เท่ากับค่าใน state อยู่แล้ว
3. หรืออย่างน้อยขึ้นบรรทัดบอกในกระเป๋าว่า "มีช่องที่แก้ค้างอยู่ รีเฟรชทั้งลิสต์หยุดชั่วคราว"

### R2 — `renderCore` สร้างตัวเลือก realm/ขั้น martial ใหม่โดยไม่คงค่าที่เลือก (ต่ำ)

`:862`, `:865` เขียน `#h_realm`/`#h_mrank` `innerHTML` ใหม่ทุกครั้งที่ `renderCore` ทำงาน โดยอ่านค่าปัจจุบันกลับมา ไม่เหมือน `drawTierFilter()` (`:726-731`) ที่เก็บค่าเดิมไว้
`dirty` กันได้แค่ `fresh()` ซึ่งเป็นคนละทาง — ถ้า `renderCore` ทำงานรอบสอง (เส้นทาง retry: `corePromise` ถูกล้างเมื่อรอบก่อนโหลดไม่ครบ หรือ `runHealth`/`checkUpdate` เรียก `getCore()` ตอน promise ว่าง) ค่าที่ผู้ใช้เลือกไว้แต่ยังไม่กดบันทึกจะถูกดีดกลับไปตัวแรก

เจอได้เฉพาะตอน chunk โหลดล้มบางส่วนแล้วผู้ใช้แก้ช่องไปแล้ว จึงเป็นระดับต่ำ แต่แก้ถูกกว่าปล่อย: เก็บ `value` ก่อนเขียน `innerHTML` แล้วคืนค่า (เหมือน `drawTierFilter`)

### R3 — `r.layers` interpolate ลง `innerHTML` โดยไม่ผ่าน `esc` (ต่ำ)

`:862` `` `${i}: ${esc(r.th)} (${r.layers} ชั้น)` `` — ช่องเดียวในไฟล์ที่ค่าจากตารางเกมไม่ผ่าน `esc` (N4 แก้ `rarDot` ไปแล้ว รอบนั้นไม่ได้แก้จุดนี้)

ความเสี่ยงจริงต่ำ (ข้อมูลมาจาก origin เดียวกัน) แต่เป็นข้อยกเว้นตัวเดียวที่เหลือ ข้อเสนอ: `esc(r.layers)`

### R4 — `isStateField` ตายแล้ว และเอกสารยังบรรยายพฤติกรรมเก่า (ต่ำ)

`:146` `const isStateField = (f) => fieldKey(f) !== null;` — ฝั่งสคริปต์ไม่เรียกที่ไหนแล้ว (grep เจอแค่ declaration, export `:311` และเทส) `dirty` ฝั่ง DOM ใช้ `LOC.fieldKey` ตรง ๆ (`:925`)
`CLAUDE.md:55` ยังเขียนว่า "`fresh()` … ข้ามรอบเมื่อ `dirty` (ผู้ใช้พิมพ์ในช่องที่ `LOC.isStateField` รับ…)" ซึ่งเป็นพฤติกรรม v3.4.3 — ตอนนี้ข้ามเฉพาะช่อง ไม่ใช่ทั้งรอบ และไม่ใช้ `isStateField`

ข้อเสนอ: ลบ `isStateField` (และเคสเทสที่อ้าง) หรือใช้มันใน listener แทน `fieldKey`, แล้วแก้ `CLAUDE.md:55` ให้ตรง v3.4.6

### R5 — เส้นทางเข้า SIM สามจุดยังไม่มี try/catch (ต่ำ)

v3.4.6 ครอบแค่ `simReady.then` (`:909-910`) ยังเหลือ:
- `:708` `showTab` เรียก `drawEvents()` ตรง ๆ — คลิกแท็บอีเว้นต์ตอน `SIM.allMajors()` throw = error ใน console ไม่มีข้อความถึงผู้ใช้
- `:774` `$('hevq').oninput = drawEvents; $('hevr').onchange = drawEvents;` — พิมพ์ค้นหาแล้ว throw ทุกคีย์
- `:1247` `setTimeout(() => { runHealth(); checkUpdate(); }, 3000);` — `runHealth` เป็น async ที่เรียก `simInfo()` (`:1200`) ซึ่งเรียก `SIM.allMajors()` ไม่มี `catch` → unhandled rejection, แผงตรวจระบบค้างที่ "กำลังอ่าน chunk หลัก…"

`buildEvents` (`:751`) กันแค่ "ไม่มีเมธอด" ไม่ได้กัน throw จากตัวเมธอด

ข้อเสนอ: ครอบ `drawEvents` ที่จุดเรียก (หรือให้ `buildEvents` มี try/catch แล้วขึ้น `EV_UNSUPPORTED` + เหตุผล) และ `runHealth()` ใน `setTimeout` เป็น `runHealth?.().catch(...)` ขึ้นบรรทัดสรุปในแผงแทนการเงียบ

### R6 — `fill('hm', t.money)` ไม่มีค่าถอย (ต่ำ)

`:937` ต่างจากช่องค่าพลังที่ใช้ `?? ''` (`:938`) ถ้า state มี `money` เป็น `undefined`/ไม่มีค่า (hook รับ object ที่มีคีย์ `money` ไม่ได้ตรวจชนิด) `input.value` จะได้สตริงที่ไม่ใช่ตัวเลข และ `fresh()` เขียนซ้ำทุก 2 วินาที

ข้อเสนอ: `fill('hm', t.money ?? '')` ให้เหมือนช่องอื่น

### R7 — `tierIdx` จำกัดแค่ด้านบน (ต่ำ)

`:99-105` `Math.min(5, n)` แต่ไม่จำกัดด้านล่าง: `tierIdx(-1)` คืน `-1` ทำให้ `itemOrder` (`:107`) เรียงไอเทมนั้นไว้เหนือ legendary และ `tierMatches` ไม่มีตัวกรองไหนรับ แต่ยังเห็นใน "ทั้งหมด" — ขัดกับสัญญาใน `CLAUDE.md` ที่ว่า "สตริงที่จับคู่ไม่ได้เห็นได้ทุกตัวกรองและอยู่ท้ายรายการ"

ใน build ปัจจุบันไม่เกิด (ไม่มี tier ติดลบ) แต่เป็นความไม่สมมาตรที่แก้ฟรี: `Math.max(0, Math.min(5, n))` พร้อมเทส

### R8 — `release.mjs` ไม่ตรวจ branch และกู้ไม่ได้ถ้า push ล้ม (ต่ำ, กระบวนการ)

`tools/release.mjs:40-42` `git add` → `git commit` → `git push` ไม่มีขั้นตอนไหนยืนยันว่าอยู่บน `main`
- รันจาก branch อื่น: commit ขึ้น branch นั้น (ถูกตามที่เครื่องมือทำ) แต่ `@updateURL` ชี้ `main` → ผู้ใช้ไม่เห็นอัปเดต และถ้า bump ใน branch ก่อน merge จะ merge ไม่ได้เพราะ `main` มี version เดียวกันแล้ว (บทเรียนใน `CLAUDE.md` §5 เขียนไว้แล้วแต่ไม่ได้บังคับในเครื่องมือ)
- ถ้า `git push` ล้มหลัง commit: รันซ้ำจะตายที่ `git commit` ด้วย "nothing to commit" — ต้องแก้ด้วยมือ

ข้อเสนอ: บรรทัดเดียว `if (run('git',['rev-parse','--abbrev-ref','HEAD']).trim() !== 'main') fail(...)` และให้ขั้น commit ข้ามเมื่อไม่มีอะไรให้ commit แต่ push ต่อ
